## 业务目标和数据边界

面向中小发行商的商务拓展/项目评审负责人，工作主线聚焦为：一轮N个候选、有限K个评审名额时，优先让哪些项目进入人工尽调。交付优先尽调名单、单项目评审卡和人工复核流程；签约与预算金额在补充成本、合同、团队和试玩信息后由发行商判断。该具体流程是根据教师反馈提出的小组应用方案，并非已经完成的真实业务试点。详见[项目提案](../Project_Proposal_Steam_Game_Success.md)。

商业评价沿用冻结的Top10%容量，在同一候选池、同一K及统一历史窗口下，比较随机选择、历史规则和ML的命中数、precision、recall及lift；说明遗漏与冷启动表现。模型比较保留组员报告的全部七个模型，历史规则另作基准。原编码LR可作为管理解读的参照，不表示排除其余六个模型；额外算法、广泛调参及SHAP按需要选择。结果应转化为具体人工调查动作，不能在没有实测结果时承诺提升。

使用Nik Davis Steam Store Games截至2019-05-01的单次快照：主表27,075行、18列，另有五张辅助表。来源与许可见[data/README.md](../data/README.md)。历史上架游戏不等同于发行商实际收到的提案池，真实应用还需带时间戳的候选资料与后续结果验证。

主标签表示观测热度和用户参与度，不等于销量、收入、利润、质量或因果效果。单次快照不能证明属性等于发售当天取值，也不能提供一致的发售后观察窗口；本项目定位为回顾性筛选原型。当前没有成本、净收入或预算约束，不能计算真实ROI、最优定价或投入金额；未经校准及外部验证的模型分数只作相对排序。此次商业聚焦不改变config或正式交接数据。

## 标签、时间切分和特征

`total_ratings = positive_ratings + negative_ratings`。在完整有效发行年份人口内计算linear 90分位，`total_ratings >= cutoff`为`hit_reviews=1`，保留边界并列及早期小样本年份。日期按UTC解析，非法日期记为`NaT`并保留诊断。2019全部排除，不能进入模型开发。

|---|---|---:|---:|

主X为24允许特征，另带关联键appid；标签、关联标识、split和发行年不得作为预测变量。主特征包括语言、年龄、五类序列属性、平台和序列计数、日历及周期编码、厂商历史。ratings、owners、playtime、SteamSpy tags/tag votes、`tag_count`及其结果派生字段禁入X；价格、成就、描述、配置、支持和媒体字段仅作未来快照敏感性分析。

developer/publisher按`;`解析，按原拼写首见去重。历史仅用严格较早发行年份；匹配任一实体的来源游戏取并集，同一appid只计一次。四个历史特征使用`log1p(N)`及`(H + 10 × 0.10) / (N + 10)`，缺失或未见厂商回退为0和0.10。已交付窗口A：2018历史可包含2017；模型和规则比较须记录并统一历史窗口。CSV和JSON-in-cell的读取要求见[解析合同](DATA_PARSE_CONTRACT.md)与[交接合同](DATA_HANDOFF_CONTRACT.md)。

## 后续建模纪律

- multi-hot/one-hot、缺失处理、标准化等学习型预处理仅在训练数据fit；验证和测试应用同一已拟合流程。
- 比较同窗口规则、Logistic Regression和一个正则化树集成模型；参数、阈值只用2017验证集选择，禁止随机切分和shuffled CV。
- 2018现作探索性复核，不再称全新盲测；报告AP/PR-AUC、ROC-AUC、Top10% precision/recall/lift及评分并列处理，并单报开发商与发行商均无更早历史的冷启动组。最终模型确认需新的未查看、时间隔离证据。
- 正类率接近10%由标签设计决定，不能证明无漂移；同年比较减少跨年累积差异，不能消除同年观察时长差异。
- 历史厂商标签仍取自2019快照，严格较早发行年不能证明真实预测时点已可观测相同信誉；结论不建立ROI。

既有2018滚动规则可行性结果为ROC-AUC 0.707903、AP 0.336896、期望Lift@10% 4.348139，历史包含2017。这些结果不是正式ML成绩，不能直接与仅用≤2016历史的模型比较；旧会议和旧alpha=20指标保持历史身份。
